# DE2Sim Requirements Compliance Matrix

Program context: Army Training Verse Challenge II, Intelligent Simulation Pipeline.

Scope of this matrix:

- Current DBbun capability is based on `paper_to_simulator_builder_v3_4.py` and the repository audit.
- Planned DE2Sim capability is based on `docs/DE2SIM_IMPLEMENTATION_PLAN.md`.
- Final UAS prototype capability refers to the planned demonstration after the relevant DE2Sim phases are implemented and validated.

Status definitions:

- Met: the current repository clearly implements and demonstrates the requirement.
- Partial: the current repository implements a related capability, but not the complete Challenge II requirement.
- Missing: the current repository does not implement the requirement in a Challenge II-relevant form.

## Current Compliance Summary

| Current status | Count | Percentage |
|---|---:|---:|
| Met | 0 / 10 | 0% |
| Partial | 5 / 10 | 50% |
| Missing | 5 / 10 | 50% |

Current compliance is deliberately conservative. The existing DBbun application is a useful content-to-simulator foundation, but it does not yet implement the planned DE2Sim ASOT, CAD/SysML ingestion, multi-fidelity generation, Godot export, packaging, or UAS demonstration.

## Planned Final Compliance Summary

| Final expected status | Count | Percentage |
|---|---:|---:|
| Met after planned DE2Sim implementation and UAS prototype demonstration | 10 / 10 | 100% |

The planned final percentage assumes successful completion of Phases 1 through 9, including the UAS demonstration package, automated validation reports, source traceability, approved AI-generated behaviors, two simulation fidelities, Godot export, packaging, and launch evidence.

## Demonstration Mapping to Evaluation Factors

| Evaluation factor | Proposed demonstration mapping | Evidence to show |
|---|---|---|
| Technical Feasibility | Demonstrate that a local engineering package can be ingested, normalized into ASOT, enriched with approved AI-generated behaviors, used to generate two simulation fidelities, exported to Godot, packaged, and validated. | CLI run logs, generated manifests, `asot.json`, simulation outputs, Godot project files, package ZIP, validation/security reports, and passing automated tests. |
| Innovation Merit | Position the ASOT-centered pipeline as the key innovation: one normalized source drives AI-assisted behavior/attribute generation, multiple fidelities, target-engine export, traceability, and reuse. | ASOT schema, provenance model, behavior candidate workflow, approval audit, and evidence that low/high simulations and Godot export derive from the same ASOT IDs. |
| Maturity | Show phased implementation with conservative scope: one target engine, documented SysML subset, referenced geometry support, approval gates, security checks, and validation reports. | Phase completion criteria, test suite results, validation/security reports, documented limitations, and no unsupported multi-engine or full-physics claims. |
| Speed to Delivery | Reuse existing DBbun ingestion, AI invocation, simulator generation, execution, validation, and documentation patterns while adding modular DE2Sim layers. | Repository audit showing reusable components; implementation plan phases; smoke tests preserving legacy CLI behavior; UAS demo rebuild command or documented sequence. |
| Value to Transition | Demonstrate a repeatable, auditable path from DE artifacts to a training-relevant executable Godot experience with reusable outputs and source traceability. | UAS demo package, packaged Godot project, launch scripts, ASOT/provenance artifacts, simulation manifests, and clear transition notes about supported formats and extension points. |

## Claims Not To Make Until Implementation Evidence Exists

- Do not claim current DBbun converts Digital Engineering packages into military simulation models.
- Do not claim current DBbun ingests or parses CAD formats.
- Do not claim current DBbun supports SysML v2.
- Do not claim current DBbun maintains an Authoritative Source of Truth.
- Do not claim `Spec.json` is a complete ASOT.
- Do not claim current DBbun generates multiple simulation fidelities from the same ASOT.
- Do not claim current DBbun exports Godot projects.
- Do not claim current DBbun produces an executable target-engine experience.
- Do not claim current DBbun creates ZIP deployment packages.
- Do not claim current DBbun deploys compiled game or simulation executables.
- Do not claim current DBbun provides full source traceability, field-level provenance, or replayable provenance.
- Do not claim current DBbun performs authoritative high-fidelity physics simulation.
- Do not claim current DBbun performs CAD round-trip, meshing, geometry-kernel operations, or unit/tolerance normalization.
- Do not claim multi-engine support until each engine has implemented exporters, tests, and demonstration evidence.
- Do not claim AI-generated behaviors are validated or approved until the approval workflow and export gates exist.
- Do not claim Army Training Verse Challenge II compliance is Met until the DE2Sim phases have produced the planned UAS demonstration evidence and automated validation results.
